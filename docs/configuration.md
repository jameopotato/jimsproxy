# Configuration Reference

Every setting JimsProxy reads, what it does, and whether you should touch it.

For setup instructions see the [README](../README.md). This page is the exhaustive reference.

---

## The file

The proxy reads **`HermesProxy.config`** — XML, from the folder containing the executable.

> The filename is `HermesProxy.config` even though the binary is `JimsProxy.exe`. The project kept upstream's name for compatibility.

The proxy re-homes its working directory to its own executable's location at startup, so the config, `CSV/`, `Logs/` and `AccountData/` are always resolved beside the `.exe` regardless of how you launch it.

### ⚠️ If you use the launcher, do not edit this file by hand

The JimsProxy Launcher **writes this file from its own template on every launch**. Hand edits are overwritten without warning. Change settings through the launcher's Settings tab instead.

This page is primarily for people running the proxy manually.

### Command line overrides

Any key can be overridden at launch without editing the file:

```
JimsProxy --set ServerAddress=logon.example.com --set ServerPort=3724
JimsProxy --config MyOtherServer.config
```

Useful for keeping one config per server. The full flag list is in the README's [Command line](../README.md#command-line) section.

## How to read this page

Keys fall into five groups, and the group matters more than the individual setting:

| Group | What to do |
|---|---|
| **Connection** | You must set these correctly. |
| **Diagnostics** | Turn on when reporting a bug, off afterwards. |
| **Tuning** | Safe to adjust to taste. |
| **Kill switches** | Leave ON. They disable shipped bug fixes. |
| **Experimental** | Leave OFF unless a developer asks you to change one. |

**Only 19 of the 40 keys appear in the shipped config file.** The rest are read but not written — they take their default unless you add them by hand. Each table below marks this in the **In file** column.

**"Default"** means the value you get out of the box: the shipped file's value for keys marked ✅, and the compiled-in fallback for keys marked ❌. Where the two differ for an ✅ key, it is called out on that row.

## Connection

The essential settings. `ServerAddress` is the only one most people change.

| Key | Default | In file | Description |
|---|---|:---:|---|
| `ServerAddress` | `127.0.0.1` | ✅ | Your server's logon address — the same thing you would put in `SET REALMLIST`. For Kronos: `login.twinstar-wow.com` |
| `ServerPort` | `3724` | ✅ | Logon port. |
| `ServerBuild` | `auto` | ✅ | Legacy server version. `auto` derives it from `ClientBuild`. Explicit values: `5875` (1.12.1), `8606` (2.4.3). |
| `ClientBuild` | `42597` | ✅ | **Must match your game client exactly** or login fails. `42597` = 1.14.2. Others: `40618` (1.14.0), `41794` (1.14.1), `40892` (2.5.2), `42328` (2.5.3). |
| `ClientSeed` | *(static seed)* | ✅ | **Do not change.** Auth-seed fallback; real per-build seeds load automatically from `CSV/BuildAuthSeeds.csv`. |
| `ServerType` | `Kronos` | ✅ | Server fork. Different 1.12 forks differ in the wire format of some CMSGs, and this also selects fork-specific item-data overlays. Values: `Kronos`, `Generic`. **`Generic` is scaffolding for future server support and is not a tested configuration today.** |
| `ReportedOS` | `OSX` | ✅ | OS identifier sent to the legacy server. |
| `ReportedPlatform` | `x86` | ✅ | Platform identifier sent to the legacy server. |
| `ExternalAddress` | `127.0.0.1` | ✅ | The address others connect to. Only relevant if you host the proxy for other people. |

> If `ClientBuild` is missing from the file entirely, the compiled-in fallback is **2.5.2 (TBC)** — not a Classic Era build. Don't delete the key.

## Ports

All four listen on `127.0.0.1` and all four must be free.

| Key | Default | In file | Description |
|---|---|:---:|---|
| `BNetPort` | `1119` | ✅ | Battle.net / portal listener. **This is the port your `Config.wtf` portal must point at.** |
| `RealmPort` | `8084` | ✅ | Realm listener. |
| `InstancePort` | `8086` | ✅ | Instance (world) listener. |
| `RestPort` | `8081` | ✅ | REST listener. |

**`BNetPort` and your client's portal must match.** `SET portal "127.0.0.1:1119"` in `WTF/Config.wtf` pairs with `BNetPort=1119`. Change one, change the other — a mismatch is the most common connection failure.

Running two proxies at once (multiboxing)? Give the second instance a different set — the launcher uses `1120 / 8085 / 8087 / 8082` — and point that client's portal at the new `BNetPort`.

## Diagnostics

Turn these on to capture information for a bug report, then turn them back off.

| Key | Default | In file | Description |
|---|---|:---:|---|
| `StructuredLog` | `true` | ✅ | Structured JSONL diagnostic events to `Logs/jimsproxy-*.jsonl`. **Leave on** — this is what makes a bug report actionable. |
| `DebugOutput` | `false` | ✅ | Extra detail in the console and logs. Turn on when reproducing a bug. |
| `PacketsLog` | `false` | ✅ | Write a full packet capture per session to `PacketsLog/`. **Large** — one file per session, and they accumulate. Only enable when specifically asked for a capture. *(The compiled-in fallback is `true`, so deleting this key turns captures on.)* |
| `VerboseLog` | `false` | ✅ | Per-packet verbose console output. Extremely noisy; deep debugging only. |
| `SpanStatsLog` | `false` | ❌ | Enables the `SpanStats` developer log category. Not useful for normal bug reports. |

## Tuning — spell timing and feel

Safe to adjust. These change how casting feels, not whether it works.

| Key | Default | Range | In file | Description |
|---|---|---|:---:|---|
| `SpellQueueWindowMs` | `400` | 0–1300 | ❌ | Width of the spell-queue hold window. A press arriving in the last N ms of an active GCD or cast bar is held and fired at expiry; earlier presses are forwarded and the server arbitrates. `400` is retail-accurate. Higher (`1000`, `1300`) feels smoother and more forgiving. |
| `SpellCastEarlyFireOffsetMs` | `0` | 0–50 | ✅ | Releases a held cast this many ms *before* the estimated GCD expiry, to compensate for latency in flight. Higher tightens the feel but risks more "Spell not ready" rejections on very low-latency connections. |
| `FormExitStartDeferMs` | `100` | 0–300 | ❌ | Druid form-exit fix (#379). After a local form cancel, defers the next cast's `SPELL_START` so the model swap renders first — without it you get a looping cast sound or stuck transform sound until `/reload`. Covers client model-swap render time, **not** latency, so do not tune it per-connection. `0` disables. |

## Tuning — gameplay and compatibility

| Key | Default | In file | Description |
|---|---|:---:|---|
| `ThreatEngine` | `false` | ✅ | Synthesizes threat data so the modern client's native threat APIs populate for threat-meter addons. Vanilla 1.12 servers never send threat over the wire. Automatically inactive in battlegrounds. Enable if you use a threat meter. |
| `EnablePallyPowerInterop` | `true` | ❌ | Translates PallyPower blessing-assignment indices between 1.12 and 1.14 so paladins on either client version can assign together without a forked addon. Strictly limited to the `PLPWR` addon prefix; no other addon traffic is touched. |
| `ClientTcpNoDelay` | `true` | ❌ | `TCP_NODELAY` on the client-facing socket. **Leave on.** `false` returns to kernel-batched (Nagle) delivery, which correlated with worse cast feel. The proxy→server socket is unaffected either way. |

## Reliability and timeouts

| Key | Default | Range | In file | Description |
|---|---|---|:---:|---|
| `AuthHandshakeTimeoutMs` | `15000` | 1000–60000 | ❌ | Bounds the logon handshake. If the login server accepts the TCP connection but never responds, login fails cleanly instead of hanging on "Connecting..." forever. |
| `EnableUnplannedReconnect` | `false` | — | ❌ | On an abrupt mid-session disconnect, attempt one cached-session-key reconnect before giving up. When off, the disconnect propagates immediately so you see "Disconnected" within a second rather than sitting in a ghost world. |
| `UnplannedReconnectTimeoutMs` | `5000` | 1000–30000 | ❌ | Hard timeout on that reconnect attempt. |

## Kill switches — leave these ON

Each disables a shipped bug fix. They exist so a developer can isolate a regression without swapping proxy builds. **If you turn one off, you are turning a known bug back on.**

None of them appear in the shipped config file; all default to enabled.

| Key | Default | Disabling it brings back |
|---|---|---|
| `StrafeCancelPreempt` | `true` | Strafing to cancel a cast takes ~700 ms to register instead of ~190 ms — the 1.14 client never sends a cancel on strafe, so the proxy synthesizes it. |
| `SynthStandOnFear` | `true` | Being feared while seated (eating/drinking) leaves you seated for the whole fear, and fear-break trinkets fail with "not standing". |
| `WorldEntryCarriedRootCure` | `true` | Movement lockup after crossing a loading boundary while the server believed you rooted (#328). |
| `LoginEvictionMerge` | `true` | A permanently hung loading screen when the server evicts you at login from a full instance. |
| `LoginPreCreateOpHold` | `true` | Input lock (cannot turn or cast until relog) on the same evicted-login path. |
| `StuckLogoutStunCancelFix` | `true` | "You can't do that while stunned" after a fast relogin following an abrupt in-combat disconnect. |
| `StuckLogoutStunClientStrip` | `true` | The client-side half of that same fix. |
| `Charm382StripPetInCombat` | `true` | Suspected cause of the severe FPS drop around player-on-player mind control in battlegrounds (#382). |

## Experimental — leave OFF

Opt-in, still under evaluation. Do not enable these because they sound good; enable them because a developer asked you to.

| Key | Default | In file | Description |
|---|---|:---:|---|
| `LowLatencyMode` | `false` | ❌ | Forwards every cast immediately instead of holding it during the GCD. Removes hold-queue races that can cause stuck spells for players under ~40 ms RTT. **Most players should leave this off** — on normal latency it makes the server reject more casts. |
| `SuppressSpellCastErrors` | `false` | ❌ | Hides transient "Spell not ready" / "Another action is in progress" errors during rapid spam. Cosmetic; independent of Low-Latency Mode. |
| `RttPrefire` | `off` | ❌ | Cast chaining across the GCD boundary. **Only read when `LowLatencyMode` is on.** `off` is plain forward-everything. `timer` holds a press arriving in the last 400 ms of the GCD and releases it at estimated expiry. Further developer-only modes exist for testing and are not supported. |
| `IdentityPinnedCastIds` | `false` | ❌ | Makes cast start↔finish pairing deterministic. **Only has any effect when `LowLatencyMode` is also on.** |
| `RefireSpellGo` | `false` | ❌ | Re-sends a stripped duplicate of an instant cast's completion event ~8 ms later, to close casts the client dropped when start and finish arrived in the same frame (stuck cast pose, looping cast sound, lit button until logout). Independent of Low-Latency Mode. |

## Keys that no longer do anything

If you find these in an old config, they are ignored and can be deleted: **`OverrideRtt`**, **`UncapFireOffset`**. The launcher strips them automatically on save.

## Minimum working config

The proxy has a compiled-in default for everything, but four keys are hard-required and validated at startup:

```
ServerAddress    ServerPort    BNetPort    ExternalAddress
```

In practice, ship the full file and change `ServerAddress`.
